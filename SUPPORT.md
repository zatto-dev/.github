# Support

How to get help, depending on what you need.

## Commercial and client support

If you are a client, or want to become one, email **hello@zatto.dev**. That address
covers project work, contracts, invoicing, support arrangements and anything about the
products we run.

Please include the product or repository name and, where relevant, roughly when the
problem started. We are a small team in Bedford, UK, and normally reply within a couple
of working days.

## Open source repositories

For repositories that are public:

- **Questions, ideas, "how do I…"** — open a GitHub Discussion on that repository if
  Discussions are enabled, otherwise an issue is fine.
- **Bugs and feature requests** — open a GitHub issue on the repository concerned, with
  the version, the steps you took and what you expected instead.

Please raise these on the specific repository rather than here. Issues on the `.github`
repository are only for the org-wide files it holds.

We triage on a best-effort basis. Open source work is not covered by a support contract
unless you have one in writing.

## Security problems

**Do not** report vulnerabilities through issues, discussions or pull requests. Follow
[SECURITY.md](SECURITY.md) instead — that means Private Vulnerability Reporting on the
repository, or **security@zatto.dev**.

## Internal planning

Backlog, priorities and delivery status are tracked in our own internal tracker, not on
GitHub. If you are asking "when will this ship", the answer will come from us by email
rather than from a GitHub label.
